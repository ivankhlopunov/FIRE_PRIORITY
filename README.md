# FIRE PRIORITY

Прототип интеллектуальной системы раннего оповещения о возможных природных пожарах по спутниковым снимкам.

# Описание проекта

FIRE PRIORITY — система, которая анализирует спутниковые снимки, определяет признаки возможного пожара и выбирает, какие данные нужно передать в первую очередь.

Главная задача проекта — помочь наземной службе быстрее получать информацию о возможном пожаре при ограниченных ресурсах спутника.

# Как работает система

Поток снимков → анализ → очередь приоритетов → передача данных → оценка результатов.

Сначала система анализирует снимки и оценивает вероятность пожара. Затем рассчитывает приоритет каждого снимка и формирует очередь передачи.

При расчёте учитываются вероятность пожара, уверенность анализа, облачность, давность снимка, повторные наблюдения территории, размер файла и время до завершения сеанса связи.

# Передача данных

Система использует три типа данных:

- alert — короткое уведомление о возможном пожаре;
- preview — облегчённая версия снимка;
- full — полный снимок.

Передача выполняется в порядке: alert → preview → full.

Полный снимок передаётся только при наличии достаточного объёма канала и энергии.

По умолчанию для передачи доступно 10% от накопленного объёма данных.

# Алгоритм FIRE PRIORITY

В проекте сравниваются два алгоритма.

FIFO — передаёт снимки в порядке их поступления.

FIRE PRIORITY — сначала передаёт снимки с более высоким приоритетом. При этом учитываются признаки возможного пожара и доступные ресурсы спутника.

# Структура проекта

app.py — пользовательский интерфейс и управление системой.

data_generator.py — создание демонстрационного потока спутниковых снимков.

detector.py — анализ изображений и поиск признаков возможного пожара.

prioritizer.py — расчёт приоритетов снимков.

simulator.py — симуляция передачи данных с учётом ограничений.

metrics.py — расчёт показателей и сравнение алгоритмов.

# Результаты эксперимента

В аварийном сценарии использовалось 60 снимков, среди которых было 5 тестовых событий. Доступная доля канала составляла 10%, запас энергии — 5 условных единиц.

Результаты FIFO:
- доставлено важных событий: 2;
- пропущено важных событий: 3;
- Recall: 40%;
- Precision: 6,9%.

Результаты FIRE PRIORITY:
- доставлено важных событий: 5;
- пропущено важных событий: 0;
- Recall: 100%;
- Precision: 17,86%.

В данном эксперименте FIRE PRIORITY показал лучший результат: система доставила уведомления обо всех пяти тестовых событиях, тогда как FIFO доставил только два.

# Запуск проекта

Создать виртуальное окружение:

python -m venv .venv

Активировать его в Windows:

.venv\Scripts\activate

Установить зависимости:

pip install -r requirements.txt

Запустить приложение:

python -m streamlit run app.py --client.toolbarMode minimal

Для генерации демонстрационных данных:

python data_generator.py

# Ограничения

Детектор является демонстрационным алгоритмом, который анализирует цвета пикселей изображения. Он не является обученной моделью машинного обучения.

Результат анализа указывает на возможный пожар, но не подтверждает его наличие.

Метка true_fire используется только для проверки качества алгоритмов. Она не участвует в анализе снимков и принятии решений о передаче.

Передача данных моделируется программно и не является реальным управлением спутником.

# Итог

FIRE PRIORITY демонстрирует, как интеллектуальная очередь может повысить эффективность передачи спутниковых данных. При ограниченных ресурсах система старается в первую очередь доставлять информацию о наиболее важных событиях, чтобы наземная служба могла быстрее получить предупреждение о возможном пожаре.
